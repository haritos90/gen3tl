These changes need two issues: game changes and notes go to the game repository; glyphs and keyboard changes go to the toolkit repository. The JSON download contains both.

A GitHub account is needed only for the issue step. The JSON file can be sent any other way.

What happens next

  1. The issue is checkedA workflow validates the changes against the current files of the project and answers on the issue with any problem; editing the issue runs it again.
  2. A pull request opensThe changes are written into the files of the project on a branch that names the issue.
  3. Checks render the boxesEvery changed line is measured against its window; a comment lists the widths and links a before and an after preview of each changed box.
  4. A maintainer merges itA maintainer reviews the pull request and merges it. After the merge a new translation has the status Translated; a text that was Approved stays Approved.
  5. A release includes itTranslated and approved texts enter the next version of the translation patch, listed on the patcher page.
  6. A playtest approves itAfter a version is played and reported in an issue of the game project, its translated texts become Approved.
